# Software domain overview

## Glossary

| Term | Definition |
|---|---|
| Software component | Traceable element of the software architecture representing an indivisible architectural element that addresses one or more needs specified by requirements applicable to the software domain. |
| Software interface | Traceable element of the software architecture defining the interaction between software components. |
| Software parameter | Traceable element of the software architecture defining configurable or fixed values that affect the software behavior. |
| Software design | Traceable element of the software architecture defining architectural decisions. |
| Software unit | Traceable element of the detailed design implemented as an independent CMake target. |
| Software integration test | Traceable element validating the software architecture. |

## Work products organization

The software domain shall be organized by process. Where applicable, processes shall have dedicated folders containing their generated work products. The structure shall be as follows:

```text
sw/
  arch/
  src/
    i_test/
      <integration_test_name>/
        doc/
        inc/
        src/
    <sw_unit_name>/
      doc/
      inc/
      model/
      src/
      u_test/
    ...
```

The `sw/arch/` folder contains the work products generated by the `sw-architecture` process (only Markdown documents: `.md`).

The `sw/src/i_test/<integration_test_name>/doc/` folder contains the work products for a specific integration test generated by the `sw-integration-test` process (only Markdown documents: `.md`).
The `sw/src/i_test/<integration_test_name>/inc/` folder contains the work products for a specific integration test generated by the `sw-integration-test` process (only C header files: `.h`).
The `sw/src/i_test/<integration_test_name>/src/` folder contains the work products for a specific integration test generated by the `sw-integration-test` process (only source files: `.c` or `.py`).


The `sw/src/<sw_unit_name>/doc/` folder contains the software detailed design Markdown document for the software unit (`<sw_unit_name>.md`).
The `sw/src/<sw_unit_name>/inc/` folder contains the work products for a specific software unit generated by the `sw-detailed-design` process (only C header files: `.h`).
The `sw/src/<sw_unit_name>/model/` folder contains the behavioral model for the software unit, when required.
The `sw/src/<sw_unit_name>/src/` folder contains the work products for a specific software unit generated by the `sw-implementation` process (only C source files: `.c`).

The `sw/src/<sw_unit_name>/u_test/<unit_test_name>/doc/` folder contains the work products for a specific unit test generated by the `sw-unit-test` process (only Markdown documents: `.md`).
The `sw/src/<sw_unit_name>/u_test/<unit_test_name>/inc/` folder contains the work products for a specific unit test generated by the `sw-unit-test` process (only C header files: `.h`).
The `sw/src/<sw_unit_name>/u_test/<unit_test_name>/src/` folder contains the work products for a specific unit test generated by the `sw-unit-test` process (only C source files: `.c`).

Software unit folders may be nested to support logical grouping and hierarchical organization according to software complexity. In folders used only for grouping (i.e., not representing a software unit), the `doc/`, `inc/`, `model/`, `src/` and `u_test/` folders shall not be present.
