# Product definition and validation overview

## Glossary

| Term | Definition |
|---|---|
| Stakeholder specification | Source information provided by stakeholders describing needs, constraints and expectations. |
| Specification | Traceable element derived from stakeholder specifications representing the smallest meaningful unit of information. |
| Requirement | Traceable element of the requirements defining an obligation to be fulfilled by one or more engineering domains. |
| Qualification test | Traceable element validating requirements using the scope, method and technology appropriate to their nature. |
| Tool | Project resource used for development, validation, or debugging. |
| External hardware documentation | Documentation for external hardware used by the project's target product. |

## Work products organization

The work products shall be organized as follows:

```text
pdv/
  spec/
    stakeholder_spec/
    stakeholder_spec_parsed/
  req/
  qf_test/
    <qualification_test_name>/
      doc/
      inc/
      src/
```

The `pdv/spec/` folder contains the work products generated by the `specs-definition` process.
The `pdv/spec/stakeholder_spec/` folder contains the stakeholder specifications for the project.
The `pdv/spec/stakeholder_spec_parsed/` folder contains generated Markdown representations of stakeholder-provided PDFs.

The `pdv/req/` folder contains the requirements work product generated by the `requirements` process.

The `pdv/qf_test/<qualification_test_name>/doc/` folder contains the work products generated by the `qualification-test` process (only Markdown documents: `.md`).
The `pdv/qf_test/<qualification_test_name>/inc/` folder contains the work products generated by the `qualification-test` process (only C header files: `.h`).
The `pdv/qf_test/<qualification_test_name>/src/` folder contains the work products generated by the `qualification-test` process (only source files: `.c` or `.py`).

## Stakeholder specifications

Stakeholder specifications shall be provided in supported document formats, for example:
- Markdown (`.md`) (recommended)
- Plain text (`.txt`)
- PDF (`.pdf`)
- Other plain text formats

Stakeholder specifications shall include:
- A high-level description of the system including objectives, expected behavior and constraints
- Tools available for the project, including usage instructions or references
- References to external hardware documentation used by the project's target product

The content shall be clear, structured and as unambiguous as possible.
